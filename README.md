## 二、启动

```bash
cd prototype
npm install
npm run dev
```

- 默认地址：`http://localhost:5173/elders`
- 端口被占用时 Vite 会自动切换，以终端输出为准。
- 生产构建：`npm run build`
- 本地预览构建产物：`npm run preview`

## 四、已覆盖能力

### 4.1 M0 平台底座与权限

- 登录：手机号 + 密码、记住账号、忘记密码（独立页面，验证码固定 123456）、演示账号一键填充；首次登录强制修改初始密码。
- 登录拦截：账号不存在、密码错误、待审核、停用、已驳回分别给出固定文案，不进入系统。
- 注册：项目注册码（4–12 位）校验后带出所属项目，注册成功即成为该项目管理员，无需审核。
- 账号来源：平台运营由部署初始化；项目管理员由项目注册链接产生；项目成员、民政查看、医保审核员由项目管理员在用户管理直接建号。
- 角色权限：平台运营、项目管理员、项目成员、民政查看、医保审核员五类角色 + 可编辑权限矩阵（覆盖 8 个模块），平台运营行只读全开。
- 注册结果：注册编号、所属项目、账号角色、已开通状态与去登录。
- 用户管理：总数、待审核、正常、停用统计；关键词/状态/角色/节点筛选；审核通过、驳回、停用、启用、重置密码、新增用户、账号调整。
- 组织与数据域：项目内组织统一为节点，可任意层级、自定义名称；支持新增子节点、重命名、启停、删除；机构池按项目隔离。
- 审计日志：登录、退出、注册、审核、账号状态、权限、通知、导出等操作留痕，支持筛选与导出确认。
- 通知配置：站内/短信/电话外呼/双向对讲开关、L3/L2 升级时限、事件模板与变量预览。
- 路由守卫：未登录访问业务页跳转登录并回原页；系统设置仅平台管理员可进，其他角色显示 403。
- 登录后角色即数据视角：民政查看账号自动进入脱敏只读视角，社区/网格账号按组织显示头部。
- 账号、会话、审计、权限与通知配置写入 localStorage，刷新后保留；可在浏览器清空 `se_platform_*` 恢复预置数据。

### 4.2 M1 老人档案与空间建模

- 以人查、以房查、以关系查三类检索与组合筛选。
- 老人档案列表、风险标签、设备在线摘要、完整度与状态。
- 一人一档五组信息的新增、编辑、必填校验与身份证重复拦截。
- 档案详情七个标签页：基本信息、居住与空间、健康与能力、社会关系、政策标签、服务与事件、变更记录。
- 房屋信息、六个房间的户型感知图、房间与设备位置编辑、进门方式维护。
- 卧室/卫生间摄像头隐私拦截。
- 门牌二维码原型示意、打印与下载模拟。
- 关系人新增、编辑、停用与紧急联系人保护。
- 档案导入三步流程：上传、校验、结果，含 6 条失败明细。
- 档案归档与在办事件阻断。
- 项目成员 / 民政查看两种视角：民政只读、身份证与手机号脱敏、隐藏编辑与建模入口。

### 4.3 M2 设备与感知接入

- 设备台账：202 台设备，覆盖 7 类设备、59 户。
- 设备列表：全部设备、离线清单、低电提醒三个视图。
- 按设备名称、SN、老人姓名、门牌、类型、社区、状态筛选。
- 新增/编辑设备：强制绑定老人、房屋与房间，SN 唯一校验。
- 摄像头安装卧室/卫生间隐私拦截，雷达安装建议。
- 设备详情：基本信息、安装位置、感知规则、隐私配置、变更记录。
- 感知规则：按设备类型展示阈值、静默时段、通知对象、升级时限与联动动作，支持恢复默认模板。
- 隐私配置：摄像头遮蔽区、工作模式、原始视频不出户；定位器可见范围。
- 离线、故障、低电状态与最近上报时间。
- 设备拆除、状态测试与变更记录。
- 与 M1 房屋房间打通：房屋页“设备台账”按老人筛选设备。
- 项目成员 / 民政查看两种视角：民政隐藏隐私配置与编辑入口，保留脱敏导出。

### 4.4 M3 居家安全事件中心

- 事件工作台：48 条事件，待处置、全部、已归档三个视图。
- L1/L2/L3 分级与响应倒计时，L3 优先、超时标红。
- 事件详情：信号证据、融合结论、通知链路、处置记录、事发快照。
- 多源融合展示：信号来源、房间、置信度、分级依据。
- L3 通知链路：0/2/5/10/30 分钟节点，物业协同标记为待 M4 开放。
- 事件处置：确认、到场、关闭归档、标记误报，状态机完整。
- L3 误报二次确认，取消不改变事件状态。
- 误报分析：误报率、原因分布、设备排行、规则调优建议与跳转 M2 调规则。
- 与 M1/M2 打通：事件详情可跳档案、设备、房屋；档案与设备页面可反查事件。
- 社区可处置、民政只读：隐藏联系电话、进门方式与处置入口。

- 社区筛选：指标、网格、排名、风险结构、设备与最近事件随范围收敛。
- 网格详情抽屉：风险分、高风险/中/低结构、楼栋排行与老人/设备/事件入口。
- 社区/网格排名：事件、高风险、在线率三个维度。
- 风险结构与高频风险标签、24 小时事件趋势、设备在线态势、最近事件。
- 驾驶舱大屏：深色 1920×1080 布局、实时钟、L3 首屏高亮、事件流、网格选中摘要。

### 4.6 M8 合规、安全与集成

- 隐私授权总览：设备安装、视频采集、定位追踪、记录仪录制四项单独同意的覆盖、待确认与撤回情况。
- 同意记录：授权编号、老人、类型、范围、签署人、渠道、有效期与状态；支持查看授权书详情、撤回授权。
- 授权撤回：必填撤回原因，撤回后状态置为已撤回，并写入审计日志。
- 调阅审批：敏感数据调阅申请、非跨域一级审批、跨域两级审批；项目管理员尝试二级审批被拦截。
- 留存策略：本地视频、事件片段、服务存证、审计日志、同意记录的留存期限与销毁方式可编辑，含范围校验。
- 销毁记录：批次、数量、大小、方式、执行人与见证人，失败批次可重试。
- 集成配置：民政、医保、公安地址库、120、119 五个集成的开关、数据范围、同步频率、配置抽屉与模拟测试连接。
- 安全基线：8 项产品侧自查、满足率、会话超时与导出管控设置、批量导出/异地登录/越权/授权到期告警处理。
- 角色可见性：平台运营与项目管理员可访问；项目成员、民政查看菜单隐藏，直接访问显示 403。
- 所有撤回、审批、策略、集成测试与告警处理写入 M0 审计日志。

### 4.7 M4 应急响应与看管任务

- 任务看板：待接单、进行中、待确认、已完成、超时退回统计，超时任务高亮。
- 任务类型：应急到场、上门探视、代购、陪同就医、检查水电、开门配合。
- 任务派发：老人、时间窗、执行人、接单/到场时限、检查清单模板、公益/计费与责任告知。
- 事件转派：M3 L3 事件详情“转派物业”，自动带入事件编号、老人与应急到场类型。
- 物业移动执行页：接单 → 确认到场 → 清单勾选 → 必拍照片 → 提交回执，状态与时间戳同步。
- 回执确认：委托人/社区确认完成、5 星评价或退回重做。
- 超时与改派：超时提示、已退回任务改派新执行人、取消任务填写原因。
- SLA 台账：平均接单、平均到场、完成率、超时任务与任务时长明细。
- 角色范围：平台运营与项目管理员可派发；项目成员仅见本人任务；民政查看无入口并 403。

### 4.8 M5 上门服务与工单

- 工单台账：10 条工单、九态状态机、6 个统计卡（待派单/待接单与待上门/服务中/待签认/待审核/异常），待派单与异常优先展示。
- 工单详情：六步进度条、工单要素、老人与进门信息、服务项目（必做/必拍/状态）、记录仪、签到记录、执行时间轴、签认、审核与回访。
- 派单与改派：老人、服务计划、地址带入；服务人员按服务项目资质校验，资质不符置灰；同一人员同时段冲突拦截。
- 服务计划：重度/中度/轻度失能三档，频次、时长（30–180 分钟）、项目必做/必拍配置与适用范围；至少 3 个项目、至少 1 个必拍项。
- 移动端今日工单：服务人员信息、资质、今日统计与工单卡片，点击进入服务执行页。
- 移动端服务执行：接单 → 上门签到（二维码 + 定位 + 人脸，偏差超 200 米记异常）→ 项目勾选与拍照 → 记录仪状态 → 服务小结（不少于 20 字）→ 提交 → 签认。
- 签到与提交校验：二维码与定位必须通过；必做项与必拍项未完成不可提交；记录仪离线需填写原因。
- 签认：老人手写、老人指纹、老人语音、家属远程签认（需手机号）、监护人代签五种方式。
- 机构审核：通过则工单完成，退回则回到服务中补充；审核意见写入时间轴。
- 异常与回访：服务人员上报拒访、不在家、身体异常等，机构填写处理结果后恢复服务；已完成工单可登记满意度、回访记录与投诉。
- 角色范围：平台运营与项目管理员可见服务工单；项目成员可执行、民政查看菜单隐藏，直接访问显示 403。
- 所有派单、接单、签到、提交、签认、审核、异常、回访与计划变更写入 M0 审计日志。

### 4.9 M6 证据中心与服务监管

- 新增医保审核员角色与预置账号，侧边栏新增“证据与监管”，仅平台管理员与医保审核员可见；社区、网格、民政直接访问显示 403。
- 待审工单：14 条审核单、5 个统计卡（待机审/机审通过/机审异常/待复核/待结算金额）、机审结论/风险/机构/时间筛选、五要素缩略（人/时/地/项/影像）。
- 全量机审：对全部待机审工单执行五要素校验，输出通过/异常与提示条数，统计与列表同步刷新；无待机审时提示“暂无可机审工单”。
- 工单取证：工单与老人信息、五要素逐项事实（异常置顶高亮）、证据时间轴、证据清单（类型/内容/时间/哈希/留存/访问范围）、记录仪片段占位、机审结论、证据访问控制、复核与申诉记录。
- 影像权限：医保专属证据仅平台运营与医保审核员可见；项目管理员与民政查看看到遮蔽提示“影像证据仅医保审核可见”，记录仪片段内容显示“已遮蔽，需医保审核授权”。
- 人工复核：机审异常与申诉工单队列，按风险与等待时长排序，超 24 小时标红；复核结论支持通过/不通过、退回原因、复核意见（≥10 字）、通知机构；高风险工单须勾选“已逐项确认异常要素”。
- 复核结果：通过进入结算池，不通过退回机构并冻结金额；机构申诉后进入申诉中，7 天内 1 次。
- 结算池：待结算明细、结算批次、拨付记录三表；按机构与周期生成批次（重度 ¥180/中度 ¥140/轻度 ¥100 示例口径），待拨付可撤回，拨付后工单置为已结算并生成拨付单号。
- 机构与人员：2 家机构卡（定点资格、合规率、绩效、工单量、异常数）、4 名人员资质与证件有效期、临期标识；点击机构卡筛选人员。
- 稽核线索：5 条线索（集中异常/影像缺失/重复申报/金额异常/设备离线），高风险提示；线索抽屉展示触发规则、关联工单、处置记录；处置支持转人工复核、标记已处理、标记不成立。
- 所有机审、复核、调阅申请、结算、拨付、线索处置写入 M0 审计日志。

### 4.10 v2.0 账号与组织治理包

- 认证统一：登录、注册、注册结果、忘记密码、首次登录改密共用 `AuthLayout`（品牌区 + 480px 表单卡，结果页 520px）；忘记密码改为独立路由，不再使用弹窗。
- 账号来源：平台运营由部署初始化；项目管理员由项目注册链接注册产生；项目成员、民政、医保、服务机构账号由项目管理员在用户管理直接创建。
- 注册链接：平台运营在项目管理生成专属链接（`/register?code=XXXX`），校验通过后带出所属项目，注册即成为项目管理员。
- 首次登录改密：管理员创建账号、审核通过、重置密码后 `mustChangePassword=true`，登录强制进入 `/change-password`，改密后进入业务系统。
- 组织维护：系统设置 → 组织与数据域支持新增子节点、重命名、启停、删除节点与机构；节点名称与层级由项目管理员自定义。
- 账号调岗：用户管理新增“调整”，可改角色与所属节点；角色切换自动带出节点或机构；禁止修改自己的角色，每个项目至少保留 1 个项目管理员。
- 组织唯一真源：`src/composables/useOrg.ts` 持久化组织与机构池，注册、新增用户、账号调整与 M1/M2/M3/M8 社区筛选均从此读取。

### 4.11 v2.0 项目化模型（项目、节点与注册链接）

- 项目模型：一个签约区县一个项目，预置 `P-AN`（安宁市 · 安宁区）、`P-NJ-LH`（南京市 · 六合区）、`P-YZ-HJ`（扬州市 · 邗江区，筹备）。
- 项目管理：`/projects` 仅平台运营可见，支持新增项目、进入项目、停用/启用、查看与重置专属注册链接；新建项目默认筹备并自动生成注册码。
- 注册链路：注册页支持 `?code=` 预填或手工输入注册码，校验通过后注册即成为该项目管理员，无需平台审核，注册时自设密码不再强制改密。
- 项目切换：平台运营顶栏显示项目切换器；切换后组织节点、机构池、账号、业务列表与统计整体切换。
- 数据隔离：`src/composables/useProjectScope.ts` 在项目变化时同步老人、设备、事件、任务、工单、授权、调阅与证据，`src/mock/analytics.ts` 提供 `refreshAnalytics()` 重算区域指标。
- 组织节点：节点不再区分街道/社区/网格，可自定义名称与任意层级；节点路径与下级节点共同构成账号数据范围。
- 通知中心：右上角铃铛聚合待人工复核、任务超时、调阅申请、账号待审核，按当前项目过滤并可点击跳转。

## 八、已知边界

- 仅实现桌面端，最小宽度 1280px；移动端与子女端、老人端不在本期范围。
- 认证与用户数据为前端 localStorage Mock，密码明文保存，不可用于生产环境。
- 权限矩阵已支持配置与保存，业务页按钮级权限拦截（新增/编辑/导出）为 P1，当前仅系统设置与合规中心按角色拦截。
- M8 电子授权书、人脸打码、声纹去除与外部集成接口均为模拟；集成测试连接不产生真实调用。
- M8 授权、调阅、留存、集成与告警数据为内存态，刷新页面后重置，用于演示审批与撤回流程。
- M4 物业端以固定物业执行人身份在手机框内模拟，不接入独立物业账号与真实定位/扫码。
- M4 计费仅登记金额与支付方式，不接在线支付；照片为占位，不上传真实文件。
- M4 任务、回执与评价为内存态，刷新页面后重置；任务操作写入 M0 审计日志。
- M5 服务人员端以固定身份「陈晓」在 390px 手机框内模拟，不接入独立服务人员账号；签到、拍照、记录仪与笔迹均为交互模拟，不上传真实照片、视频与签名。
- M5 工单、签到、签认、审核、异常与回访为内存态，刷新页面后重置；工单操作写入 M0 审计日志。
- M5 工单详情页的六步进度条首步为「待接单」，未派单工单以顶部提示条与「派单」按钮区分。
- 演示状态开关为全局模拟，不影响真实会话与账号状态。
- 大屏驾驶舱为独立路由 `/dashboard`，按 1920×1080 基准画布等比缩放并铺满视口，只读展示，处置回事件中心。
- 户型图为固定网格布局，不支持拖拽绘制与真实尺寸测量（P2）。
- 新增/编辑抽屉固定 960px / 720px，窄屏下不做响应式收窄。
- 所有数据为内存 Mock，刷新即重置，不接后端接口。
- 设备在线率、离线与低电数量为演示样本，用于验证异常视图，不代表真实运营数据。
- 事件通知、双向对讲、视频确认、120/119 联动均为原型模拟；物业协同在 M4 开放。
- 事件与设备数据刷新后重置，处置结果不跨刷新保留。
- 区域一张图为网格示意图，不含真实 GIS；驾驶舱按 1920×1080 设计，社区事件趋势按今日事件是否为 0 做空态处理。
- M6 审核单、证据、复核、结算与线索为内存态，刷新页面后重置；机审结果与复核状态不跨刷新保留。
- M6 影像、哈希、打码、拨付凭证均为交互模拟，不接入真实视频流、加密与财务系统。
- M6 医保审核员为新增预置角色；若浏览器保留旧版 `se_platform_*` 数据，需清空 localStorage 后重新登录才能看到 13800000004 账号。
- 组织与账号的持久化键为 `se_platform_projects_v4`、`se_platform_project_v1` 与 `se_platform_users_v2`；项目开通、节点维护、项目切换、账号调岗、改密在刷新后仍保留。
- 多项目为前端归属模拟：项目、组织节点、机构、账号与审计日志按 `projectId` 隔离；老人、设备、事件、任务、工单、授权、调阅与证据按当前项目收敛。
- 数据区域（如「华东 · 南京」）仅为签约信息标识，原型不做物理分库或行级隔离，落地方式属研发实现设计。
- 平台运营跨项目排障无审批流，仅在项目管理页提示原则。
- 组织节点与业务数据在原型中按「节点名称」匹配，研发落地需改为节点 ID 关联；节点重命名会影响按名称的历史筛选。
- 权限矩阵覆盖 8 个模块（含任务、工单、证据），项目成员与民政查看按角色拦截；按钮级权限尚未接入。
- M5 完成工单不会自动生成 M6 审核单，两个模块使用独立演示数据；跨模块数据打通列为 P1。
